# 当前控制算法与系统架构

## 1. 项目分层

```text
┌─────────────────────────────────────────────┐
│ CoppeliaSim / 真实 UR5                      │
│ UR5、焊枪、焊丝、工件、传感器与控制器状态     │
└───────────────┬─────────────────────────────┘
                │ /joint_states 或 RTDE
┌───────────────▼─────────────────────────────┐
│ MATLAB 规划层                                │
│ 场景几何、IK、ACCP、RRT/RRT-Connect      │
│ 碰撞检测、轨迹验证、时间参数化、MAT 导出       │
└───────────────┬─────────────────────────────┘
                │ /joint_trajectory（仿真）
┌───────────────▼─────────────────────────────┐
│ ROS2 / HMI 控制层                            │
│ rclpy 控制节点、官方 UR 驱动、轨迹门、安全门   │
└─────────────────────────────────────────────┘
```

### 仿真控制链

```text
MATLAB 规划/验证
    → /joint_trajectory
    → ros2_ws/src/ur5_controller/ur5_controller/controller.py
    → ZMQ Remote API（23000）
    → CoppeliaSim UR5
    → CoppeliaSim simROS2 publisher
    → /joint_states
    → MATLAB 或 HMI 状态显示
```

外部 `rclpy` 节点负责控制订阅；CoppeliaSim 内部只发布状态。早期不稳定的
simROS2 Python subscriber 方案已放弃，不应重新启用。

### 真机控制链

```text
真实 UR5 CB3
    ↔ 官方 UR ROS2 Driver / RTDE
    ↔ ur5_hmi 状态监视与轨迹客户端
    ↔ Final Execution Check
    ↔ 人工确认后才允许 FollowJointTrajectory
```

当前真实 TCP、真实工件坐标和焊枪安装几何仍存在版本/参考系差异，真机焊接执行门保持
BLOCKED；离线预演不等于真机可执行。

## 2. 连续焊缝算法：ACCP

正式入口：

[`replan_weld_actual_axis_adaptive_feasibility.m`](</home/ttbstt/jixiebi/UR5/matlab仿真/replan_weld_actual_axis_adaptive_feasibility.m>)

核心实现：

[`replan_weld_actual_axis_adaptive_core.m`](</home/ttbstt/jixiebi/UR5/matlab仿真/replan_weld_actual_axis_adaptive_core.m>)

候选 IK：

[`generate_actual_axis_ik_candidates.m`](</home/ttbstt/jixiebi/UR5/matlab仿真/generate_actual_axis_ik_candidates.m>)

### 算法流程

```text
同一条真实焊缝与焊接侧约束
        ↓
16 个稀疏初始规划点
        ↓
连续 IK：上一点关节解/分支参考作为下一点 seed
        ↓
节点限位、TCP 姿态、焊接侧、机器人/焊枪/焊丝/工件/自碰撞检查
        ↓
失败区间局部二分与自适应插点
        ↓
必要时有限 beam 与局部角度冗余恢复
        ↓
选择性 TCP 执行点修正
        ↓
Forward 失败后才尝试 Reverse，并重新定义焊缝 tangent/travel
        ↓
整条路径节点 + 插值边 + TCP 精度复核
```

当前冻结配置：

```text
initialPoints          = 16
maxRefinementRounds    = 4
maxPoints              = 40
maxSegmentTcpErrorMm   = 0.5
maxIntermediatePoints  = 4
endMarginM             = 0.025
enablePostRecovery     = true
joint continuity       = 15 deg hard constraint
```

算法不是把 80 个点全部做独立 IK，而是先稀疏规划，再只在 IK 失败、碰撞、关节跳变或
TCP 段间误差超限的局部区段加点。最终输出同时包含规划关节路径和执行/验证路径。

### 已验证性能参考

方案① `branchReferenceOn` 的冷启动测试（6 个 seed）：

```text
规划算法时间中位数   3.203 s
规划算法时间 P90     3.782 s
IK 调用中位数        334
规划点中位数         16
执行点中位数         24
最大 TCP 段误差      0.4267 mm
最大关节跳变         8.786 deg
```

这些是冻结仿真场景下的离线结果，不代表真实工件/真实 TCP 已完成验收。

## 3. 自由空间算法：RRT 系列

代码目录：[`RRT`](</home/ttbstt/jixiebi/RRT>)

基础算法包括：

- `RRT_basic.m`：基础单树 RRT；
- `RRT_connect.m`：双树 RRT-Connect；
- `RRT_star.m`：RRT*；
- `Bi_RRT.m`、`Bi_RRT_star.m`：双向版本；
- `FastConnectAnytimeRRTStarJoint.m`：Constraint-aware Bidirectional RRT* (CBi-RRT*)；
- `ClassifiedRRTStarJoint.m`、`BiRRTStarJoint.m` 等对比实现。

关节空间规划器的共同约束：

1. 状态为 UR5 六维关节角 `q ∈ R^6`，单位 rad；
2. 随机采样、最近邻、目标偏置、固定步长 steer；
3. 新节点检查关节限位、机器人/焊枪/焊丝/工件/自碰撞；
4. 每条边执行关节插值碰撞检查；
5. 最终路径再用更密分辨率独立复核；
6. 接近段和退出段分别规划，不重新规划已经通过的焊缝段。

HMI 中自由空间算法可选 `RRT`、`RRT-Connect`、`Bi-RRT*` 和默认的
`Constraint-aware Bidirectional RRT* (CBi-RRT*)`。焊缝段固定使用 ACCP，不会被自由空间算法下拉框替换。

### 3.1 当前自由空间 RRT 的真实工作方式

自由空间 RRT 不是在焊缝 80 个点之间重新搜索，而只处理两个关节空间任务：

```text
qHome     → qPreWeld       接近工件
qPostWeld → qHome          完成焊接后的撤离
```

每个状态都是六维关节角 `q∈R^6`（rad）。规划器在 UR5 关节限位内随机采样，默认目标偏置
`0.20`，以最近邻为基础按最短关节角方向扩展，单步最大约 `12°`。两棵树交替生长：一棵
从起点扩展，另一棵通过 `CONNECT` 连续追赶新节点；两树接通后回溯得到路径。

搜索过程中的每个新状态和每条关节插值边都检查：

```text
UR5关节限位
UR5自碰撞
UR5与工件碰撞
焊枪 GunCollisionHull 与工件碰撞
MATLAB wireCollision 与工件碰撞
```

搜索内部边分辨率为约 `2°`；得到路径后再用约 `0.5°` 高密度分辨率重新复核。因此 RRT 的
“找到路径”不等于直接执行，必须通过独立后验验证。

### 3.2 CBi-RRT*：首解优先的 FastConnectAnytimeRRTStar

当前自由空间算法中最有代表性的自研版本是
`FastConnectAnytimeRRTStarJoint.m`。它不是单纯的 RRT*，而是两阶段结构：

```text
Stage 1：原有双树 RRT-Connect，快速寻找首条可行路径
Stage 2：保留两棵树，执行 ChooseParent/Rewire，继续改善 best-so-far 路径
```

它增加了状态/边缓存、邻域候选、路径代价统计和时间检查点。工业运行可以在 Stage 1
得到首条认证路径时立即停止；离线实验则可以继续 Stage 2，观察路径长度随时间的改善。
这与焊缝 ACCP 的“正常快速、失败后恢复”思想一致，但服务的是自由空间段。

已经验证的任务划分是：

```text
Task A：qHome → qPreWeld，再做 PreWeld → Point 1 局部连接
Task B：Point N → qPostWeld 局部连接，再做 qPostWeld → qHome
```

现有 `RRTConnectJoint`、`BiRRTStarJoint`、`ClassGoalLiteJoint` 和
`ClassifiedRRTStarJoint` 是统一碰撞/关节度量下的对比实现；CBi-RRT* 是“RRT-Connect 首解 +
Bi-RRT* 局部优化”的自研自由空间版本。它不能与论文复现的 Gao-AR-RRT* 混称。

## 4. Full Welding Task 组成

```text
RealHome
   ↓  RRT / CBi-RRT*：自由空间接近
PreWeld
   ↓  局部连续连接
Point 1 → … → Point N：ACCP 焊缝运动
   ↓  局部退出连接
PostWeld
   ↓  RRT / CBi-RRT*：自由空间撤离
RealHome
```

HMI 任务类型：

- `RealHome → PreWeld`；
- `Weld Seam`；
- `PostWeld → RealHome`；
- `Full Welding Task`。

每一段均记录路径点数、时长、碰撞、连续性、TCP 误差和最大关节跳变，Full Task 还记录
approach/weld/exit 分段结果。

工具层级：

```text
connection/WeldingGunMount
├─ WeldingGun_visual
├─ GunCollisionHull（4 个凸组件）
├─ wireCollision（MATLAB 碰撞模型中的细圆柱）
└─ WeldTCP
```

工件使用 4 个简化 collision box。所有规划碰撞体统一到 MATLAB UR5 base frame。

需要特别区分：

- `GunCollisionHull` 和 `wireCollision` 是规划碰撞代理，不等于真实 CAD；
- 历史记录中的 18 mm 焊丝长度、1.2 mm 直径尚未由实物测量最终确认；
- 当前真实控制器 TCP 与 HMI 已应用规划 TCP 存在约 35.197 mm 的位置差异；
- 因此真实 TCP/焊丝轴线/导电嘴中心没有完成统一验收前，不能把仿真轨迹直接用于真机。

## 6. 当前代码版本关系

项目现在同时保留“运行源”和“交接副本”：

```text
运行源（唯一用于运行/修改）
├─ UR5/matlab仿真/
├─ RRT/
├─ UR5/ur5_hmi/
└─ ros2_ws/src/ur5_controller/

交接副本（只读参考）
└─ UR5/机械臂控制算法/源码副本/
   ├─ MATLAB/
   ├─ RRT/
   ├─ HMI/ur5_hmi/
   ├─ ROS2/ur5_controller/
   └─ 场景几何/
```

副本用于答辩、代码审阅和离线交接，不自动参与 MATLAB path、HMI 启动或 ROS2 构建。
如果副本需要修改，必须先与运行源比较，再同步回运行源并更新交接文档；不能直接在副本
上启动真机或仿真控制。
