# HMI 连续规划窗口无响应调查与修复

## 已证实的原因

不是 MATLAB 没有启动，也不是本次优化未收敛。原 HMI 的 ROS worker 每20ms处理一次回调，多种状态回调都会向主线程发送状态。主线程每个通知都执行完整显示刷新、执行门和新增执行准备区域检查。

414点原始预览在 `planning_busy=true` 时的30次真实 MainWindow 刷新性能分析：平均118.731ms/通知，最大142.755ms；读取并解析 RealHome YAML 共120次，执行上下文90次，版本绑定150次。YAML解析累计3.011s，占全部3.562s约84.5%。新增区域使原本一次的配置读取变成每帧四次，且原始预览本来就不能进入执行软件验收，仍先做了昂贵读取。事件服务速度不足，主线程积压，系统出现 not responding，QProcess进度和完成信号也延迟。

原请求 `prepare_20261019_103553_826984`：MATLAB报告于10:43:44生成，HMI完成回调记录在10:55:58，额外延迟约734s；process_and_transfer_sec=1204.222s，不能把它解释成纯算法耗时。报告 success=true、continuous_planning_status=PASS、executionReady=false，46801控制器等价采样，轮廓0.266538mm、同步0.478806mm、姿态0.299963°、最大速度0.083001283rad/s、最大加速度0.259063731rad/s²，碰撞/关节限位/版本离线门PASS。离线PASS不等于物理验收。

## 最小修复

- `ur5_hmi/gui/main_window.py`：状态通知只存最新快照并保留执行记录采样；主线程以100ms显示定时器合并刷新。失去运动就绪状态立即禁用执行；人工发送前仍检查最新状态。规划期间执行门明确BLOCKED，不重复全路径/执行证据计算。
- `ur5_hmi/gui/execution_preparation_panel.py`：删除额外的1秒全门轮询；原始预览在磁盘读取之前被拒绝进入执行验收；每次更新只计算一次软件原因；有效上下文按数据/报告/几何与配置文件内容身份复用，RealHome文件变更必须重读，不能复用旧PASS。规划期间只显示等待，不显示软件PASS。
- 不修改 RealHome保存/读取格式，不改变实时反馈新鲜度、数值精度、碰撞/限位和发送前校验。没有新权限或执行许可文件。

`before/refresh_profile.*`、`after/refresh_profile.*`、`after/display_refresh_profile.txt`保存性能明细。`qt_replay/responsiveness_tests.json`和`vtk_replay/responsiveness_tests.json`保存事件循环结果；`execution_regression/simple_execution_tests.json`保存软件门结果。测试使用合成、未就绪的50Hz状态源，ROS线程和RTDE自动读取均关闭。QProcess是真实异步子进程，但只重放已保存的真实MATLAB报告；不是新的完整优化验收，也不声称完成物理/伺服验证。测试产物隔离在UI_FIXTURES，Home使用历史测试YAML，原报告及生产YAML没有被测试改写。

初期VTK测试夹具有生命周期错误：临时替换的Python方法被Qt定时器捕获后释放，导致测试自身崩溃/异常。改用全局持久禁用回调后，实际VTK回放通过；没有为此修改生产VTK模型代码。

## 使用注意

旧HMI进程不会热加载源文件，需要关闭旧窗口再打开，避免多个实例并行。旧请求的优化文件已保留。用户在调查期间又保存了新的RealHome，不能把旧请求的离线PASS当作新Home下的可执行许可；现有版本检查继续生效。

MATLAB算法运行时长没有因本次GUI修复而缩短；本轮消除的是窗口事件积压。完成时图表生成仍可能短暂停顿约2.6秒，与原先持续不响应、十余分钟完成通知延迟不同。

CBi-RRT*、ACCP-D、IK、TCP、机器人/枪/丝/工件/地面几何、碰撞规则与阈值、ROS2执行链均不变。NO ROBOT MOTION。
