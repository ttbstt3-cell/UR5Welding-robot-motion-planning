# 我的机械臂控制算法思路

## 0. 整体算法思路

整个系统采用“**场景同步 → 任务分段 → 分层规划 → 严格验证 → 轨迹交付**”的思路，而不是让一个算法同时处理所有问题：

```text
读取 CoppeliaSim 场景/真实机器人状态
              ↓
统一 UR5 base、关节顺序、TCP 和工具碰撞模型
              ↓
把完整任务拆成：接近段 → 焊缝段 → 退出段
              ↓
接近/退出段：关节空间 RRT 系列搜索自由空间路径
焊缝段：     ACCP 按焊缝顺序连续求解
              ↓
拼接三段路径并做整条路径验证
              ↓
时间参数化、MAT/JSON 导出、HMI 预演
              ↓
通过 Final Execution Check 后才允许人工确认执行
```

其中最重要的分工是：

1. **RRT 负责自由空间**：解决机器人从 RealHome 到 PreWeld，以及从 PostWeld 回到 RealHome 的避障问题。
2. **ACCP 负责焊缝空间**：焊缝顺序、TCP 位置和焊接姿态已经确定，重点是保持 IK 分支连续并避开局部障碍。
3. **验证层负责最终裁决**：任何一段只有同时通过关节限位、节点碰撞、插值边碰撞、TCP 精度和连续性检查，才能进入下一层。
4. **HMI 负责交付而不是替代规划**：HMI 读取 MATLAB 结果、预演和做安全门，不在 GUI 中偷偷生成另一套路径。

这个结构的核心目标是：对规则焊缝尽快得到第一条完整可执行轨迹；只有失败区段才增加计算量，避免所有任务都运行昂贵的全局随机搜索。

## 0.1 自由空间 RRT：我的另一条规划算法

焊缝规划和自由空间规划不是同一个问题。焊缝段的 TCP 目标位置、焊接侧和工作姿态已经
确定，适合使用连续 IK；而从机器人 Home 到焊接预备位、以及收焊位回 Home 的路径没有
固定焊缝约束，适合在六维关节空间使用 RRT。

我的自由空间 RRT 输入和输出为：

```text
输入：qStart、qGoal、UR5/焊枪/焊丝/工件完整碰撞模型
状态：q = [q1 q2 q3 q4 q5 q6]，单位 rad
输出：qPath，N×6 关节路径
```

基本 RRT-Connect 流程如下：

```text
在关节限位内随机采样 qRandom（带目标偏置）
              ↓
在当前树中找最近节点 qNear
              ↓
沿最短关节角方向固定步长 steer
              ↓
检查新节点和 qNear→qNew 的插值边
              ↓
另一棵树对 qNew 执行 CONNECT，连续扩展直到 REACHED/TRAPPED
              ↓
两棵树接通后回溯得到 qPath
```

当前 UR5 自由空间规划的具体约束是：

- 两棵树分别从起点和目标点生长，交替扩展；
- 采样在 UR5 关节限位内进行，默认目标偏置为 `0.20`；
- 单次关节扩展步长为 `12 deg`，使用最短旋转角差；
- 搜索边内部按约 `2 deg` 分辨率插值检查；
- 每个节点和每条边都检查关节限位、UR5 自碰撞、焊枪、焊丝、工件碰撞；
- 规划成功后再用约 `0.5 deg` 的更密分辨率独立复核，避免搜索分辨率造成漏碰撞；
- 固定随机种子时结果可复现；首条完整可行路径通过后即可停止。

自由空间只规划两个任务：

```text
qHome     → qPreWeld       接近路径
qPostWeld → qHome          撤离路径
```

`PreWeld → Point 1` 和 `Point N → PostWeld` 是端点局部连接；`Point 1 → Point N` 始终由
ACCP 负责，RRT 不会替换已经确定的焊缝轨迹。

### 我的 CBi-RRT* 改进：Fast-Connect Anytime RRT*

在基础 RRT-Connect 之上，我实现了 CBi-RRT* 版本：

```text
Stage 1：双树 RRT-Connect，尽快找到第一条可行路径
             ↓ 找到后保留两棵树
Stage 2：Bi-RRT* 风格 ChooseParent + Rewire
             ↓
       按关节路径代价继续改善 best-so-far 路径
```

CBi-RRT* 的改进点是：

1. **首解优先**：先解决“能不能通过”，不让路径优化阻塞首条可行路径；
2. **树保留**：不丢弃 Stage 1 已经建立的双树；
3. **ChooseParent/Rewire**：在邻域内选择更低代价父节点，并重连已有节点；
4. **缓存**：缓存已检查的关节状态和边，减少重复碰撞计算；
5. **Anytime**：首解可立即输出，也可以在时间预算内继续优化路径长度；
6. **统一后验验证**：无论是首解还是优化后的路径，都必须通过同一套高密度碰撞复核。

因此，CBi-RRT* 不是把 ACCP 改成 RRT，而是专门用于焊缝前后的自由空间段。完整任务仍然是：

```text
RRT/CBi-RRT* 接近 → ACCP 焊接 → RRT/CBi-RRT* 撤离
```

项目中还保留 `BiRRTStarJoint`、`ClassGoalLiteJoint` 和
`ClassifiedRRTStarJoint` 作为自由空间算法对比实现；它们不是焊缝主算法，也不是
Gao-AR-RRT*。二维 `RRT_basic/RRT_star/...` 文件主要用于算法演示和基准测试，不是当前
UR5 六维任务的最终控制器。

## 1. 要解决的问题

船舶格子间中的焊缝通常是有明确顺序的连续直线或分段曲线。机器人不只是要到达若干离散
目标点，还必须同时满足：

- 焊丝/TCP 始终沿真实焊缝运动；
- 焊枪保持正确焊接侧、工作角和行进角；
- 焊枪、焊丝、机械臂和工件全程无禁止碰撞；
- 相邻关节构型连续，不能出现腕部突然翻转；
- 规划时间足够短，适合工业现场快速重规划。

传统做法把焊缝密集采样成 80 个点，对每个点重复做大量 IK 或在整个关节空间随机搜索。
这会带来两个问题：计算量大，以及前面一个错误的 IK 分支会把后面的连续焊缝带入死路。

## 2. 核心思想：利用焊缝连续性代替全局暴力搜索

我的方法不是一开始就构建整条焊缝的全局大图，而是把焊缝看成一条有序连续任务：

```text
焊缝几何和焊接姿态已知
          ↓
先用少量关键点建立一条连续关节轨迹
          ↓
只在困难局部增加搜索和采样
          ↓
找到第一条完整可行轨迹后立即停止
```

因此算法的计算量主要花在真正困难的区段，而不是平均分配到整条焊缝。

## 3. ACCP 五个关键机制

### 3.1 稀疏初始化

先用 16 个规划点描述整条焊缝，起点和终点保留 25 mm 端部余量。规划点不是最终执行点，
只是用来快速选择 IK 分支和检查可行性。

### 3.2 连续 IK continuation

求解第 `i+1` 个焊点时，优先使用第 `i` 个焊点的关节解作为 IK seed，并用已确认的起焊
构型作为分支参考：

```text
q(i) → IK seed → q(i+1) → IK seed → q(i+2)
```

由于相邻焊点空间距离很小，IK 通常可以沿同一连续分支快速收敛，避免大量随机初值。

### 3.3 可行性自适应细分

如果某一段出现 IK 失败、节点碰撞、插值边碰撞、关节跳变过大或 TCP 段间偏差超限，
只对该段二分并重新求解：

```text
Pi ───────────── Pi+1
          ↓ 失败
Pi ───── Pmid ───── Pi+1
```

这使规划点数量由算法根据轨迹难度决定，而不是固定使用大量点。当前最多 4 轮局部细分，
规划点上限为 40。

### 3.4 条件恢复，而不是全程高代价搜索

正常 continuation 失败后，才逐级启用有限恢复：

```text
beam=1 快速路径
    ↓ 失败
beam=2/3 保留少量 IK 分支
    ↓ 仍失败
局部 travel/roll 角度冗余
    ↓ 仍失败
局部确定性恢复或反向规划
```

恢复只作用于失败窗口，不让所有普通任务都承担全局图搜索的代价。

### 3.5 Forward/Reverse 方向级联

焊缝几何不变，但从哪一端开始做 continuation 会影响 IK 分支传播。因此先尝试：

```text
Point 1 → Point 2 → … → Point N
```

如果失败，再重新计算反向 tangent/travel，尝试：

```text
Point N → Point N-1 → … → Point 1
```

这不是打乱焊点顺序，而是利用同一条焊缝的两个物理焊接方向，低成本寻找互补 IK 分支。

## 4. 严格验证不因提速而省略

每个候选节点和相邻边都检查：

```text
关节限位
UR5 连杆与工件
焊枪碰撞代理与工件
焊丝碰撞代理与工件
机器人自碰撞
TCP 位置/姿态误差
焊接侧和工作角约束
```

最终还要对整条执行路径进行高密度插值复核，检查节点之间的实际 TCP 曲线，而不能只看
焊点节点误差。当前 TCP 段间误差阈值为 0.5 mm，连续关节跳变硬约束为 15°。

## 5. 与 Gao-AR-RRT* 的方法区别

Gao-AR-RRT* 主要在冗余姿态和关节空间中进行随机扩展、连接和优化；我的方法利用了焊缝
顺序已知这一结构，把问题分成：

```text
焊缝段：连续 IK + 局部自适应恢复
自由空间段：RRT / RRT-Connect / CBi-RRT*
```

这样做的目标不是在每个场景寻找大量候选最优轨迹，而是在满足全部硬约束的前提下，尽快
找到第一条可执行轨迹。这也是 ACCP 在规则船舶焊缝中减少 IK 调用和规划时间的主要原因。

## 6. 工业运行策略

```text
输入焊缝任务
    ↓
Forward ACCP
    ↓ 成功：立即输出
    ↓ 失败
Reverse ACCP
    ↓ 成功：立即输出
    ↓ 失败
局部恢复/人工诊断
    ↓
完整节点、边、TCP 和碰撞验证
    ↓
输出 MAT/JSON，交给 HMI 预演和执行门
```

“成功”的定义是一条焊缝任务找到一条完整可行轨迹，而不是要求每个随机 seed 都成功。
HMI 在真实机器人上仍必须经过起点、实时状态、安全模式、TCP/工件版本和人工确认门。
